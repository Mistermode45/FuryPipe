# Provider Execution Audit Chain\n\n## Purpose\n\n`createProviderExecutionAuditChain()` links the three existing plaintext-free provider receipts into one deterministic audit manifest:\n\n~~~text\nProvider Attempt Plan Receipt\n        ↓\nProvider Attempt Context Runtime Receipt\n        ↓\nGoverned Provider Execution Receipt\n        ↓\nProvider Execution Audit Chain\n~~~\n\nThe chain does not execute anything and does not replace any source receipt.\n\n## What it verifies\n\nThe chain verifies:\n\n- canonical SHA-256 integrity of all three source receipts;\n- exact provider/model/workload continuity across all stages;\n- Context Optimizer profile state continuity from planning to runtime;\n- exact final prompt identity from Context Runtime to the executed request;\n- exact prompt identity from planning to Context Runtime when no context was injected.\n\n## Context injection limitation\n\nWhen Context Runtime injects optimized context, the planning receipt and context receipt deliberately represent different prompt stages.\n\nThe receipts alone do not contain enough plaintext-free material to cryptographically replay and prove that transformation.\n\nThe chain therefore records:\n\n~~~text\nplanningToContextPrompt = context-transformed-not-verifiable-from-receipts\n~~~\n\ninstead of inventing a stronger provenance claim.\n\nThe final Context Runtime prompt must still match the execution request exactly by prompt digest, source digest and byte count.\n\n## Receipt integrity is not provenance\n\nA correct receiptDigest proves that the serialized receipt fields are internally consistent with that digest.\n\nIt does not prove who created the receipt.\n\nThe chain preserves the source receipt provenance semantics:\n\n~~~text\nplanningReceipt          = not-verified\ncontextRuntimeReceipt    = not-verified\nexecutionRequestReceipt  = process-local-verified\nexecutionPermitReceipt   = process-local-verified\nexecutionOutcomeReceipt  = not-verified\nchainProvenance          = not-verified\n~~~\n\n`chainProvenance = not-verified` is intentional. V1 is not a signed or remote attestation.\n\n## Context profile continuity\n\nThe planning and runtime receipts must agree on the exact Context Optimizer profile state:\n\n~~~text\nIDENTITY\nQUALIFIED\nBLOCKED\n~~~\n\nFor `QUALIFIED`, profile ID and profile digest must also match exactly.\n\nFor non-qualified states, neither receipt may expose an applied profile identity through the chain.\n\n## Plaintext-free output\n\nThe chain stores only:\n\n- exact scope;\n- source receipt digests;\n- prompt/request continuity status;\n- execution protocol and request digest;\n- execution outcome kind;\n- provider evidence classification;\n- provenance classifications;\n- its own chain digest.\n\nIt does not copy:\n\n- task text;\n- prompt text;\n- context plaintext;\n- response bytes;\n- provider request IDs;\n- permit IDs;\n- policy IDs;\n- credentials;\n- pricing source text.\n\n## Canonical chain digest\n\n`chainDigest` is SHA-256 over a key-sorted canonical JSON representation of the chain core.\n\nChanging any linked receipt changes the chain identity.\n\n## Verification helper\n\n`verifyProviderExecutionAuditChain(chain, input)` reconstructs the expected chain from the supplied source receipts and verifies the canonical chain digest.\n\nIt verifies structural linkage to those receipts, not signed source-object provenance.\n\n## Public package surface\n\n~~~ts\nimport {\n  createProviderExecutionAuditChain,\n  verifyProviderExecutionAuditChain,\n} from 'furypipe/provider-execution-audit-chain';\n~~~\n\nInstalled-tarball smoke coverage verifies this public subpath.\n\n## Security semantics\n\nThese distinctions remain mandatory:\n\n~~~text\nreceipt digest integrity != trusted provenance\nstructural continuity != provider attestation\ntransport-reported != verified\nprocess-local provenance != persistent signed provenance\nplanning != context execution != provider execution\n~~~\n\n## Current limitations\n\nV1 does not provide signed receipts, remote timestamps, cross-process provenance, automatic persistence, or cryptographic proof of the planning-to-context transformation when optimized context was injected.\n
