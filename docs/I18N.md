# FuryPipe i18n runtime core

## Status

`PARTIAL_SURFACE_WIRING`

The locale engine and tests exist. The human-readable `doctor` CLI surface now
consumes message IDs and accepts an explicit BCP-47 locale; dashboard and
other surfaces are not yet migrated. This document must not be interpreted as
end-user FR/EN completion.

## Implemented

- BCP-47 validation/canonicalization through `Intl.getCanonicalLocales`.
- deterministic exact → language → default fallback;
- FR and EN core catalogs;
- locale direction for common RTL language families;
- pseudo-locales:
  - `en-XA` accented;
  - `ar-XB` bidi/RTL;
- placeholder-safe pseudo-localization;
- named interpolation;
- exact machine-value identity helper.

## Non-translatable values

Machine/protocol values do not belong in message catalogs:

- code;
- JSON/YAML;
- file paths;
- IDs;
- hashes;
- signatures;
- model/provider identifiers;
- protocol messages;
- exact values.

Use human-facing message IDs around those values and preserve the machine value unchanged.

## Integration gate

Before changing the status from `IMPLEMENTED_NOT_WIRED`:

1. inventory CLI/dashboard human strings;
2. migrate one surface at a time to message IDs;
3. keep protocol/log machine fields stable;
4. run FR/EN integration tests;
5. run `en-XA` layout tests;
6. run `ar-XB`/RTL layout tests for web surfaces;
7. verify locale selection and fallback in packaged runtime;
8. keep unknown message IDs fail-visible instead of fabricating text.

The current CLI proof is limited to `doctor --locale=fr`; it does not prove
dashboard, MCP, browser, or RTL visual integration.

The isolated core is owned by the ChatGPT parallel track under `src/i18n/**` and `tests/i18n.test.ts`.
